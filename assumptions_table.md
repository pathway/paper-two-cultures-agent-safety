# Unified assumptions table: classical RL vs LLM agents

!!! warning "Status: STARTED"
    Not final. Not fully human-reviewed. See [the AI-use statement](../ai-use.md).


*v0.1, 2026-11-20. Companion to `framing.md`. Extends the precondition list P1–P7 in `../rebuttal-agent-safety-rl/draft.md` §6.*

## How to read it

- Each row is one **axis**, stated neutrally. Both cultures fill it in.
- **Owner** says whose default assumption the row tests:
  - **RL**: a classical-RL assumption that fails for LLM agents.
  - **LLM**: an LLM-agent assumption that fails in typical RL.
  - **Both**: each side assumes something the other side breaks.
- **RL exceptions** names the RL sub-literature that already relaxes the assumption. This is the steelman column. A row with a strong exception is weak evidence for a culture split.
- "Classical RL" means the Sutton–Barto setting [1] as used in safe RL [2, 3, 4]: a learner, a designer-written reward, a designed environment, episodic resets.

## Row groups and the Breiman section each mirrors

| Row group | Breiman section mirrored | One-sentence reason |
|---|---|---|
| A. Objective | §5 "The use of data models" and §5.2 on goodness-of-fit | "Assume the agent maximizes R" is "assume the data are generated by the following model"; a satisfied constraint has no power outside the abstraction, as a passed goodness-of-fit test has none in high dimensions. |
| B. Learning | §5.3 "Multiplicity of data models" and §8 Rashomon | Many rewards fit one behavior, as many models fit one data set; the "internalized reward" is one picture among many. |
| C. Environment and state | §6 "The limitations of data models" | The deployment environment "stopped looking like a nail": non-episodic, adversarial, real; the toolkit is frozen at CMDP, safe exploration and shielding. |
| D. Actions and observations | §9 Occam, and §10 Bellman's curse (folded in) | The MDP abstraction is simple and wrong about open-ended actions whose safety depends on context; accuracy, not formal tidiness, is the goal. |
| E. Overseer | §7 "A new research community" and §11 "Information from a black box" | The behavior-modeling community formed around oversight; CoT monitoring extracts intent from the agent black box as permutation importance extracted structure from the forest. |
| F. Validation | §5.4 "Predictive accuracy" plus the Efron comment | Both cultures measure where their instruments reach; the Efron objection ("prediction by itself is only occasionally sufficient") applies to evals as to forests. |

## The table

| # | Axis | Classical RL default | LLM-agent default | Owner | RL exceptions (steelman) | Safety consequence |
|---|---|---|---|---|---|---|
| **A. Objective** |||||||
| A1 | Who sets the objective | Designer writes R before training; fixed | Prompt and tool outputs set the effective objective at run time [5, 6] | RL | Goal-conditioned RL takes a goal as input, but from a designer-known goal space [7] | Untrusted content can rewrite the objective (prompt injection [6, 8]) |
| A2 | Is the objective exogenous to the observations | Yes: observations cannot change R | No: instructions and data share one token stream [9] | RL | Corrupted-reward channel [10], delusion box [11]; both assume a known corruption model | Reward arrives over an unauthenticated channel; a security problem, not a noise problem |
| A3 | Form of the task specification | Scalar reward function | Natural-language instruction, written by a non-expert, at test time [12, 13] | LLM | Language-conditioned RL [14] | Task is ambiguous by construction; the agent must infer intent |
| A4 | Can the principal's preferences be steered by the agent | No: R is fixed | Yes: sycophancy, induced preference shift, misleading the evaluator [15, 16, 17] | RL | Assistance games [18] model a human, but with exogenous preferences | The target moves under optimization; POMDP planning assumes it does not |
| A5 | Can the cost or unsafe set be written before deployment | Yes: joint limits, hazard lists [4] | No: open-world, normative, context-dependent | RL | Shields over finite abstractions [3]; impact measures need no cost [19, 20] | CMDPs and shields cover only the enumerable subset [debunking §5.4] |
| **B. Learning** |||||||
| B1 | Does the policy learn at deployment | Yes: training and acting are one loop | No: weights frozen; adaptation only in context [12] | RL | Offline RL, fixed-policy evaluation | Safe-exploration methods have nothing to modify [21] |
| B2 | Does a reward signal arrive at deployment | Yes, each step or episode | No | RL | Inverse RL infers a reward, but it is not identifiable [22, 23] | "Internalized reward" claims cannot be tested |
| B3 | Where competence comes from | Reward-driven trial and error from scratch | Pretraining on human text; post-training steers it lightly [12, 24] | Both | Pretrained representations in robotics RL | Behavior is not the argmax of any one reward; reward-based diagnosis misattributes |
| B4 | Does the agent bring human norms | No: tabula rasa | Yes: inherits norms, and their violations, from human text | LLM | None classical | Some safety is free; some failure is human-like (deception, concealment) |
| B5 | Who controls exploration | Designer (ε-greedy, entropy bonus, safe-exploration rules) | No designed exploration; actions come from sampling a prior | RL | — | "Unsafe exploration" relabels an action-selection error |
| **C. Environment and state** |||||||
| C1 | Who built the environment | Experimenter; usually a simulator | Nobody: real software, real internet, real users | LLM | Sim-to-real transfer [25] | No safe place to fail; evaluation is not the deployment distribution |
| C2 | Episodes and resets | Many episodes; failures amortize [4] | Single-shot; many actions irreversible | RL | Reset-free and single-life RL | Expected-cost guarantees are the wrong metric; tail matters |
| C3 | What the state contains | Physical or game state; Markov in a designer-chosen representation | Includes the user's intent and the world beyond the context window | RL | POMDPs with belief states [26] | The belief over intent is the alignment problem, not a filter |
| C4 | Is anything in the environment adversarial | Usually nature only | Yes: content authors attack the agent [6, 8] | LLM | Robust and adversarial RL [27, 28] | A security threat model is required; average-case RL guarantees do not hold |
| C5 | Other agents | Single agent, or designed multi-agent games | Other LLM agents, copies of itself, unknown humans [29] | LLM | Multi-agent RL | Collusion and miscoordination risks that single-agent safety cannot see |
| **D. Actions and observations** |||||||
| D1 | Action space | Fixed, small, known semantics | Open-ended text and tool calls; composable; semantics depend on context | RL | Large discrete action spaces, but enumerable | `rm -rf /tmp/x` vs `rm -rf /`: the same action type, opposite safety |
| D2 | Can the agent explain itself | No | Yes: verbal reasoning traces, partly monitorable [30, 31] | LLM | — | New oversight channel; it degrades if trained against [32] |
| D3 | Can the agent be steered without retraining | No: change R and retrain | Yes: system prompt, instructions, few-shot examples [12] | LLM | Goal-conditioned policies [7] | Cheap control, and cheap attack, through the same channel |
| **E. Overseer** |||||||
| E1 | Does the agent model its overseer | No | Yes: knows what evaluation and oversight are [33]; can fake alignment [34] | RL | Delusion box [11]; reward tampering in causal-influence diagrams | Optimizing against a monitor hides misbehavior rather than removing it [32] |
| E2 | Who is in the loop at run time | Nobody; autonomous after training | User approves steps, co-acts, and often disables gates [debunking §7] | LLM | Human-in-the-loop RL from preferences is a training-time loop [35] | Shields have a friction cost; human factors become part of safety |
| E3 | Who owns training | The same team designs R, trains and deploys | Model is a third-party product; the deployer cannot retrain | LLM | — | Deployment-time safety must be architectural, not learned [36, 37] |
| **F. Validation** |||||||
| F1 | How safety is measured | Expected return and expected cost under a known R and C | Attack success rates, eval pass rates, incident records [8, 38] | Both | — | RL measures inside its model; LLM evals measure on a sample. Both are weak in the tail. |
| F2 | Is the eval itself a specification that can be gamed | Reward is gameable; the test environment is not modeled by the agent | Evals are gameable and the agent can detect them [33] | LLM | Specification gaming literature [39] | Behavior culture inherits Goodhart too; neither culture escapes specification |

## Notes for the paper

- **The split is symmetric.** About as many LLM-side assumptions fail in RL as the reverse. This supports the two-cultures framing over a pure "RL is wrong" framing.
- **The LLM rows are not all advantages.** D2 and D3 give new control channels. C4, C5 and E3 add threats RL never modeled.
- **Strongest rows for the paper:** A2, B1, A5, E1. Each has the RL side's own authors stating the precondition [3, 4, 10, 21].
- **Weakest rows:** B5 and D1. RL people will say large or structured action spaces are an engineering extension. Keep them, but do not lean on them.
- **Bellman folded in.** Dimensionality as curse lives in A5 and D1; the only blessing that survived scrutiny, CoT monitoring, lives in E under Breiman §11 (see `framing.md` §3.5).
- **Rows that cut against the behavior culture:** F1 and F2. Put them in the final remarks, as Efron's objection: prediction alone is "only occasionally sufficient" [40].
- **Use as an instrument.** Each row is a yes/no check. For any proposed method, mark which rows its preconditions need. This generalizes the transfer test of the debunking draft.
