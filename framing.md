## 0. One-paragraph thesis

Breiman [1] split statistics into a **data modeling culture** ("assume the data are generated by the following model", validate by goodness-of-fit) and an **algorithmic modeling culture** (treat the inside of the box as unknown, validate by predictive accuracy on a test set). Agent safety has the same split, and the same epistemic move marks the line. One culture begins "assume the agent maximizes a reward R", derives safety from that model (constrained MDPs, shields, safe exploration), and validates by constraint satisfaction inside the model's abstraction. The other treats the trained agent as a black box, measures what it does (red-team success rates, evals, incident records), and bounds harm by architecture rather than by proof. McLean et al. [2] is the exhibit that makes the split visible: it hypothesizes an "internalized" reward f(o_p, o_g) for a frozen LLM policy and reasons from it, which is "assume the data are generated by the following model" in RL dress. The debunking draft [3] shows that this move fails on one paper. The two-cultures paper asks why the move is made at all, who makes it, what it costs the field, and what each culture cannot do without the other.

## 1. The mapping, line by line

Breiman gave each culture four lines: what is inside the box, the approach, the validation, the population. The same template for agent safety:

| | Breiman: data modeling | Breiman: algorithmic modeling | Agent safety: **objective-modeling culture** | Agent safety: **behavior-modeling culture** |
|---|---|---|---|---|
| The black box | nature: x → y | nature: x → y | the agent: (observations, prompt) → actions | the agent: (observations, prompt) → actions |
| What is assumed inside | a stochastic model with parameters | unknown; "complex, mysterious, partly unknowable" | an optimizer of a designer-known R (or an "internalized" R) over a known state abstraction | unknown; a pretrained artifact with latent dispositions, lightly steered by post-training |
| The opening sentence | "Assume that the data are generated by the following model: …" [1, §4.1] | "find a function f(x)" [1, §1] | "Assume the agent maximizes R(s, a) …" / "the agent has internalized f(o_p, o_g)" [2, §4] | "We ran the agent against N attacks / tasks and observed …" |
| First question asked of a new problem | "What's the model for the data?" [1, §4] | "How well does it predict on a test set?" | "What's the reward function? What's the cost function?" [2]; CPO takes C_i as input [4] | "What does it do when we run it?" [5, 6] |
| Validation | goodness-of-fit tests, residual plots | test-set error, cross-validation | constraint satisfaction, formal guarantee inside a finite abstraction [7], Safety Gym cost [8] | attack success rate [5], eval pass rate, incident databases [9], monitor catch rate [10] |
| Theory | inference, asymptotics, hypothesis tests | generalization bounds, capacity | regret bounds, CMDP duality, shield correctness, convergence | threat models, control protocols [11], scaling of eval results, security design patterns [12] |
| Where the hard part is relocated | into the choice of model | into the choice of test distribution | into the specification of R, C, the unsafe set | into eval coverage and the threat model |
| Characteristic failure | a model that passes the checks and is wrong about nature | distribution shift | a specification that is satisfied and a system that is unsafe ("moves the alignment problem around" [8, §3.3]) | a tail event no eval covered |
| Home venues | Annals, JASA | NeurIPS, Machine Learning | ICML/NeurIPS RL tracks, L4DC, safe-RL workshops | alignment labs, security venues (AISec, OWASP [13]), SE venues (ICSE [14]), blogs, incident reports |
| Population (Breiman's guess: 98% / 2%) | | | measured in §4a | measured in §4a |

**Reading the table.** Every row has a one-to-one analogue except population, which Breiman guessed and we can measure. The two "where the hard part is relocated" rows are the honest core: both cultures relocate the problem rather than solve it. Breiman said the data modelers' goodness-of-fit tests "have very little power unless the direction of the alternative is precisely specified" [1, §5.2]. The analogue holds exactly: a shield proves safety only against the automaton's labels [7, §9]; a constraint is satisfied only for the cost you wrote [4]. The behavior culture's analogue failure is the Efron objection (§5 below): a test set says nothing about the tail.

## 2. Why the mapping runs RL ≈ statistics, not RL ≈ machine learning

This needs stating early because RL people will object. In robotics, RL *is* the algorithmic culture against classical control. The mapping here is by epistemic move, not community label. The move that defines Breiman's data-modeling culture is: *posit a parametric model of the inside of the box, then reason from the model as if it were the mechanism.* Safe RL inherits exactly this move from control: posit R and the constraint set, then the conclusions (safe, within budget, shielded) are about the model's mechanism, not the agent's. Breiman's sentence transfers verbatim: "The conclusions are about the model's mechanism, and not about nature's mechanism" [1, §5]. Replace "nature" with "the agent".

The parallel also holds sociologically:

- Breiman: the new community (ML) "sprang up" outside statistics, "mostly young computer scientists" working on problems "where it was obvious that data models were not applicable" [1, §7.1]. Here: LLM-agent safety sprang up outside RL, in labs, security teams and SE groups, on systems where it was obvious a cost function could not be written.
- Breiman: statistics' tools "are frozen at discriminant analysis and logistic regression" [1, §6]. Here: the safe-RL toolkit named in [2] is CMDP (1999), shielding (2018), safe exploration (2012), Safety Gym (2019), applied unchanged to a 2026 artifact.
- Breiman: "the field has a vested interest in data models, come hell or high water" [1, §12]. Here: the vested interest is in the reward-maximizer picture, which is what makes decades of theory applicable.
- Breiman: "If all a man has is a hammer, then every problem looks like a nail. The trouble for statisticians is that recently some of the problems have stopped looking like nails" [1, §6]. This sentence can open the paper.

## 3. Skeleton: the assumptions table is the paper

Breiman's paper is 12 numbered sections plus a glossary, then four invited comments and a rejoinder. The two-cultures paper keeps Breiman's opening (§§1–4) and closing (§12), and replaces his middle (§§5–11) with the six row groups of `assumptions_table.md`. Bracketed numbers follow this file's bibliography, not the table's. Each body section states, for its row group: the classical-RL default, the LLM-agent default, the RL steelman (the "RL exceptions" column), and the safety consequence. Breiman's named lessons are attached to the row group where they belong instead of standing alone.

### 3.4 Reading the table as the paper

- **Rows are claims; sections are row groups.** Every body section argues its rows and nothing else. A reviewer who rejects a row rejects a paragraph, not the paper.
- **The "Owner" column sets each section's tone.** RL-owned rows (A1, A2, A4, A5, B1, B2, B5, C2, C3, D1, E1) are where the objective-modeling culture is wrong about LLM agents; these carry Breiman's §§5–6 polemic. LLM-owned rows (A3, B4, C1, C4, C5, D2, D3, E2, E3, F2) are where the behavior-modeling culture faces problems RL never had, and where it borrows RL's habit of stating assumptions. "Both" rows (B3, F1) go to the final remarks.
- **The "RL exceptions" column is the built-in rejoinder.** Breiman had Cox and Efron to steelman him; a position track has nobody. Each section must engage its exceptions column before stating its consequence.
- **Breiman's named lessons attach to row groups, not sections of their own.** No power of goodness-of-fit → A. Rashomon → B. Limitations of the frozen toolkit → C. Occam → D. New community and information from a black box → E. Predictive accuracy and the Efron objection → F.
- **The evidence items of §4 each anchor to rows.** Census → §1 population and E (the new community). Coverage count → A5, D1. Rashomon demo → B2, B3, with the three stories drawn from A (misspecified reward), E1 (oversight evasion) and A2 (unauthenticated control plane). Transfer test → every row read as a yes/no precondition; the debunking draft's P1–P6 are A1, A4, A5, B1, C2, E1.

### 3.5 Bellman decision: cut as a section, keep the curse

**Decision.** Do not give "dimensionality: curse or blessing" its own section. Fold the curse into rows A5 and D1 (no enumerable unsafe set; the same action type is safe or catastrophic by context). Move the one genuine blessing, chain-of-thought monitoring, to row group E under Breiman's §11 "information from a black box", where the analogy is tight.

**Reasoning.** The test was: at least two concrete, cited results showing a safety capability with no classical-RL counterpart, and an analogy to Breiman's "more variables, more information" that is tight rather than decorative.

- *CoT monitoring.* One concrete result: Baker et al. show CoT monitoring is "far more effective than monitoring agent actions and outputs alone" and that GPT-4o can monitor o3-mini [10]. No classical-RL counterpart: an Atari policy has no legible intent trace. But the same paper shows the channel degrades under optimization pressure, and Korbak et al. is a position statement that calls the opportunity "fragile" and "imperfect", not a result [27]. Count: one result, one position.
- *Instructability (D3).* A capability, but it has a counterpart in goal-conditioned RL [28], and it is the same channel as prompt injection (A1, A2). It is not a safety blessing; it is a double-edged control surface.
- *Natural-language constraints.* AgentSpec is a DSL of triggers, predicates and enforcement actions over an enumerable rule set, with over 90% prevention on code agents [14]. This is a shield [7] with a nicer front end. It has a classical counterpart by construction.
- *Tightness.* Breiman's blessing is that the *predictor* uses more features and extracts information "in small pieces" [1, §10.1]. The agent-safety blessing is that the *overseer* reads more output. The roles differ, so the analogy is decorative. Where the analogy is tight is Breiman §11: extracting information about the mechanism from a black box without a data model. CoT monitoring is exactly that, so it moves to E.

**Result.** One of two required results, counterpart-free; analogy decorative. Cut. The curse side stays as evidence in A5 and D1, and the blessing side becomes two sentences in §9 (row group E).

## 4. What makes it a paper, not an essay

Breiman had two kinds of evidence: twenty years of accuracy wins (Tables 1–2, Statlog ranks 1,1,1,1) and the hepatitis re-analysis. The two-cultures paper needs its own evidence, or it is an opinion piece. Four candidates, ranked by value per effort:

1. **A measured census (replaces Breiman's 98/2 guess).** Build the citation graph of safe-RL and LLM-agent-safety papers from OpenAlex [21] or Semantic Scholar. Measure: do the two literatures cite each other? Cluster the graph and report the cross-cluster citation rate. Count authors who publish in both. Breiman guessed; we count. This is the single most novel contribution and it is cheap. Anchors: §1 population line and row group E (the new community).
2. **A specification-coverage measurement (the "no power" claim made concrete).** Take the AI Incident Database [9] entries involving LLM agents, and classify each: could the harm have been written as a cost function or safety automaton before deployment, yes or no, with the rule written out when yes. Report the fraction. This is the analogue of Breiman's seven-dimensional simulation where goodness-of-fit tests "did not reject linearity until the nonlinearity was extreme" [1, §5.2]. Anchors: rows A5 (cost not writable before deployment) and D1 (action safety depends on context); feeds F1.
3. **A Rashomon demonstration.** One incident (Replit), three formal stories (misspecified reward; oversight-evading policy; unauthenticated control plane), each internally complete, each prescribing a different remedy. Mirrors Breiman's three five-variable regressions "within 1.0% of each other" [1, §8]. Anchors: rows B2 and B3 (reward not identifiable from behavior); the three stories are drawn from A (misspecified reward), E1 (oversight evasion) and A2 (unauthenticated control plane).
4. **The transfer test, generalized.** Lift the precondition checklist from [3, §6] into a general instrument: for any "X is a Y problem" claim, list Y's method preconditions and check them. Used once in [3]; here it becomes the paper's reusable tool, applied to RL → agents and, for symmetry, to security → agents and to evals → agents. Anchors: every row of the table read as a yes/no precondition; the debunking draft's P1–P6 are rows A1, A4, A5, B1, C2, E1.

Items 1 and 2 are measurements made in this work. Item 3 is a worked example. Item 4 is the method.

## 4a. Results so far, and a pivot in the claim (2026-11-20)

- **Census:** the split is visible in the citation graph without our labels. Louvain purity 0.92; cross-corpus references 0.13% (A→B) and 0.23% (B→A). Nearly all contact runs through the term "reward hacking". Breiman's 98/2 guess becomes a measurement.
- **Coverage count:** a pre-deployment rule could have blocked first-order harm in 86% of 103 LLM-agent incidents (yes 43%, partial 44%). Every `no` is an attacker-operated agent. The "no power" claim of §4 item 2 is **not supported as stated**.
- **Operator split and rule kind:** deployer-operated incidents (N=64): yes 61%, partial 39%, **no 0%**. Attacker-operated (N=35): no 40%. Of 89 writable rules, 88 are tool-layer access control (allow/deny-list 78%, approval gate 61%, least privilege 39%, egress/DLP 35%); **1 is a CMDP-style cost over the policy**. Gate present but switched off: 16% of incidents.
- **Catalog and combined:** over the 70-row catalog (N=66 after vetoes) yes 55% / partial 44% / no 2%; deployer-operated no = 0. Combined AIID + catalog, deduplicated, N=148: yes 46%, partial 45%, no 9%, all 14 `no` attacker-operated. CMDP-style cost: 1 of 154 writable rules. Robust across two independently assembled sets.
- **The pivot.** The writable rules are tool-layer access control, not costs over the agent's objective. So:
  - The objective-modeling culture is right that constraints work, and wrong about where they live: in the tool layer, not in R.
  - The behavior-modeling culture is right that the objective cannot be specified, and wrong if it concludes that nothing can be written.
  - The residual no rule covers is concealment, intent-indistinguishable misuse, and legitimate-looking injected instructions (rows E1, A2, C3).
  - Where rules existed they were disabled or bypassed (row E2). Human factors, not writability, is the binding constraint in the headline cases.
- **Breiman analogue shifts** from "goodness-of-fit has no power" (§5.2) to Hoadley's reply: black boxes run in production only inside written constraints that clients, law and drift demand. The paper's recommendation becomes Hoadley's score engineering for agents, with the measured residual as the open problem.
- **Taxonomy mapping, N=70:** McLean's three classes fit 53% of incidents, none fits 47%; the class label is unstable under prompt rewording (kappa 0.25) while operational facts are stable (kappa 0.86–0.90). On the cannon unified taxonomy, the response that would have prevented or caught the incident is area 10 runtime control in nearly every case (10.3 safeguards/access restriction 86%, 10.2 monitoring 63%); formal guarantees (11.1) and specification work score 0. RL-native problem areas (3.1, 3.2, 4.2) cover ≤ 20%; injection (4.3) covers 70%.
- The 15-incident sample has not been human-audited.

## 5. Where the analogy breaks, and the paper must say so

Breiman wrote from a position of strength: the algorithmic culture was winning on the one metric both cultures accepted. The behavior-modeling culture in agent safety has no such scoreboard. Writing the paper as "RL loses" would be wrong and would be refused by reviewers from the RL side. The honest asymmetries:

- **No shared metric.** Breiman could put x down both boxes and compare y. In safety, the quantity of interest is the rate of rare catastrophic events, which neither culture can measure in advance. The paper should say that the behavior culture's "test set" is as weak in the tail as the objective culture's constraints are outside the abstraction.
- **The Efron objection transfers.** Efron: "Prediction by itself is only occasionally sufficient," and "Numerical experimentation by itself, unguided by theory, is prone to faddish wandering" [1, Efron comment]. For agents: a passed eval has no confidence interval over deployments, and the behavior culture has no theory of when its measurements generalize. The objective culture at least knows what it assumed. Breiman conceded the related point that "'Importance' does not yet have a satisfactory theoretical definition" [1, Rejoinder].
- **The Cox objection transfers.** Cox: "Often the prediction is under quite different conditions from the data," and "Better a rough answer to the right question than an exact answer to the wrong question" [1, Cox comment]. Breiman agreed on the first point. For agents, every deployment is prediction under changed conditions. The question "will this agent delete the database" is about a mechanism, and mechanism-free measurement cannot answer the counterfactual. Interpretability is the behavior culture's attempt at mechanism; it is immature.
- **The Hoadley point transfers.** Hoadley's credit scorers put "score engineering" constraints on black-box models because clients, law and drift demanded it [1, Hoadley comment]. This is the hybrid the paper should recommend: a behavior-measured agent wrapped in written constraints over the enumerable subset.
- **Evals are specifications too.** The behavior culture writes evals; an eval is a specification of what counts as failure. It inherits Goodhart when the agent models the eval [10, 22]. The debunking draft's P6 (the agent models the monitor) cuts against both cultures. This should be stated in the final remarks, not hidden.
- **Breiman's resolution does not fully transfer.** Breiman dissolved the Occam dilemma: "the goal is not interpretability, but accurate information" [1, §11]. For safety, accurate information about past behavior is not enough; the goal is a bound on future harm. No black-box method gives one. The paper's final remarks should propose what each culture must borrow: the objective culture must give up the fiction that R is known and adopt measurement; the behavior culture must adopt the objective culture's habit of stating assumptions so that its measurements have a domain of validity.

Recommended stance: Breiman's structure and tone in §§1–11, then a §12 that is more balanced than Breiman's, because the evidence is.

## 7. Naming the cultures

Breiman named each culture by what it puts inside the box: a data model, or an algorithm. Options here:

| Name pair | For | Against |
|---|---|---|
| objective-modeling / behavior-modeling | mirrors "data modeling / algorithmic modeling"; names the epistemic move | "behavior modeling" is a term in psychology |
| specification culture / empirical culture | plain | "empirical" sounds like a compliment; RL people run experiments too |
| reward culture / observation culture | short | "reward modeling" collides with Leike et al.; "observation" collides with POMDP vocabulary |
| RL culture / agent culture | what people actually say | names communities, not moves; invites the "RL is empirical" objection of §2 |

Recommendation: objective-modeling and behavior-modeling. State in §1 that the names denote moves, not tribes, and that many people make both moves.

## 8. Follow-ups to Breiman worth citing

Breiman's paper generated a literature on itself. The most useful for this paper:

- Shmueli, "To Explain or to Predict?" [24]: formalizes the explanation/prediction distinction Breiman left informal. The agent analogue is "to specify or to measure".
- Donoho, "50 Years of Data Science" [25]: the sociological sequel; the two cultures became one field with a new name. Worth asking whether agent safety will do the same.
- Efron, "Prediction, Estimation, and Attribution" [26]: Efron's considered 2020 position, two decades after his comment on Breiman; the best source for the "prediction is not enough" objection.
- The 2021 Observational Studies retrospective issue on Breiman's paper (*Observational Studies* 7(1), 2021).
